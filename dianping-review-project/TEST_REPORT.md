## 端到端演示

执行 `scripts.make_demo` 生成 3 张明确标记的合成重叠截图，再以 `--fixture` 输入预置 OCR 行，完整运行处理及导出。输出：3 个评论候选、1 个未拼接/非评论片段；3 个候选进入演示主表，4 个记录进入质量表；0 个自动确认完整的评论。此演示不是 OCR 精度测试，更不是真实用户数据。

模拟中断重跑和 UI 交互亦纳入上述 54 项自动测试。发现并修复了截图底部下一条昵称误混入、以及缓存嵌套列表被合并操作修改导致续跑不一致的问题。

核心实际测试使用 Pillow 11.3.0、NumPy 2.3.5、OpenCV 4.10.0、pandas 2.3.3、openpyxl 3.1.5、PyYAML 6.0.2、pytest 8.4.2、Streamlit 1.66.0。OCR 已安装 PaddleOCR 3.7.0、PaddlePaddle 3.3.1，但未成功下载模型。

CI 已配置 Linux/Python 3.12 与 Windows/Python 3.11 的合成测试任务，**尚未确认远端 CI 的执行结果**。CI 不启动微信、不下载 OCR 模型，也不替代真实截图验收。

## 未解决、不可声称已验证的项目

1. Windows 10/11 的实际鼠标、DPI、窗口焦点、滚轮位移和暂停快捷键体验。云端没有本地桌面访问能力。
2. 实际大众点评微信小程序布局的边界、昵称/等级区域、图片区域和星形图标变体。默认所有自动候选保留 `layout_uncalibrated` 标记。
3. 中文识别精度及官方模型端到端推理。请在本地允许官方模型下载，或使用配置中的可信本地模型目录。
4. 折叠正文不会自动点击展开；用户需手动展开并补拍。OCR 错字和缺字不自动“补全”。
5. 无足够重叠、跨屏 OCR 冲突、相同短句及同日相似正文必须人工核对；不得把候选数量或截图数量当真实评论总数。
6. 自动照片检测可能漏检或误检，安全边距也有损失正文的可能。真实样本验证前不能承诺完全无个人信息混入，导出分享前应逐条检查。
7. 不判断平台是否允许自动化，不保证不触发限制，也不能自动可靠识别验证码。遇到验证/限制人工立即停止。
8. 数据量约 300 条尚未实测性能，也未声称采到全部可访问评价。
